## 1. 产品目标

**一句话**：在不改变用户可见行为的前提下，消除部署链路隐患、降低后端读路径资源开销、并让大列表（公司 / 人员 / 任务）在千级数据下保持流畅滚动与快速响应。

**可量化成功指标（落地后验收基线）**：
- **部署**：Render 生产构建阶段不再触发 MongoDB 二进制下载（构建日志无 binary download，构建失败率 → 0；生产镜像体积下降）。
- **后端读路径**：对 `companies` / `tasks` / `meetings` / `documents` 等列表 / 详情接口，`.lean()` 前后用 `autocannon` 对比，读接口 **P95 下降 ≥ 20%**（建议先记录 baseline 再改）。
- **前端大列表**：在造数 1000+ 条的 Companies / Personnel / Tasks 列表中，滚动 **帧率 ≥ 50fps**（React DevTools Profiler / Chrome Performance 验证）；父组件 state 变更（搜索框输入、弹窗开关）不再触发未变化行重渲染。
- **质量门禁（工程师 / QA 必须遵守）**：ESLint **0 Error**；`vite build` **0 Error**；现有 `server/tests/*` **全绿**。

> 沙箱限制：连不上 Atlas（mongodb.net 被网络拦截），后端真实 DB 端到端测试受限；以 mock + 单元 / 组件层测试为主，压测类指标在可联网环境或 CI 中复核。

## 4. 关键技术方案要点

### 4.1 虚拟化 vs 服务端分页取舍
- **本次选择：A. 客户端虚拟化（react-window）** —— 与 2.1 一致。理由：前端当前即「全量取数 + 全量渲染」模式，虚拟化零后端改动、纯前端收益、风险最低、落地最快；可与 3.2 服务端分页并存（见下）。
- **取舍对比**：

  | 维度 | A. 客户端虚拟化（本次） | B. 服务端分页 + 无限滚动 |
  |---|---|---|
  | 后端改动 | 无 | 需 3.2 + 前端取数联调 |
  | 传输量 | 仍全量拉取（首屏慢） | 最小（仅当前页） |
  | 超大数据集 | 首屏拉取慢 | 友好 |
  | 实现风险 / 工作量 | 低 / 中 | 高 / 大（前后端联调） |
  | 滚动体验 | 即时流畅 | 依赖取数 + loading 态 |

- **结论**：本轮先虚拟化（可视区渲染，立即见效）；3.2 后端分页契约同步落地以减少响应体；前端分页「取数 + 无限滚动」是否同步，取决于 §5 Q2。二者可叠加：未来切服务端分页后，虚拟化仍负责可视区渲染。

### 4.2 `.lean()` 风险点
- **丢失项**：Document 实例方法（`.save()` / 后续链式 Document 操作）、虚拟字段（virtuals，除非 `.lean({ virtuals: true })`）、部分 getter 行为与原型链。
- **写路径排除**：任何「读取后需 `entry.save()` / `doc.updateOne` 链式依赖 Document」的场景，保留完整 Document，**不加 `.lean()`**。
- **populate 组合**：`.populate(...).lean()` 合法；但若 populate 目标后续需 `save()` 则不可 lean。
- **实施建议**：脚本化批量替换只读路径 → 保留写路径 → `server/tests/*` 全绿验证；上线前用 grep 复核「`.lean()` 之后仍有 `.save()` / 实例方法调用」的误伤（见 §5 Q4）。

### 4.3 分页契约 schema
- **统一响应体**（字段名需与既有分页接口对齐，见 Q3）：
  ```json
  {
    "page": 1,
    "limit": 50,
    "total": 1234,
    "pages": 25,
    "items": [ /* 当页数据 */ ]
  }
  ```
- 默认 `limit=50`；`page` 从 1 起；`pages = Math.ceil(total / limit)`。
- 已分页接口（companies / personnel / audit / search / resultsTimetable）字段名可能不同（如 `data` vs `items`），**须先核对统一**，避免六列表改完字段前后端不一致。

### 4.4 巨组件拆分边界
- **父组件（AdminPanel / CompanyDetail）**：仅持 Tab 选中态 + 布局 + 共享 id / companyId，通过 props 下传；不持有各 Tab 内部数据 state。
- **子组件**：每个 Tab / Section 独立组件，自持内部 state + 自定义 hooks（`useCompanyTasks`、`useRuleLibrary`、`useMeetingSignatures` 等），数据获取 / 派生逻辑进 hooks。
- **拆分粒度**：以现有 Tab 为天然边界；每个子文件目标 < 400 行；共享 UI（Modal / 表格 / 表单）抽 `components/`。
- **约束**：等价重构，零行为变更；先建测试 / 截图基线再拆，确保回归一致。
