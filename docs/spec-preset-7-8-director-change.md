## 0. 通用约定（两份模板共用）

| 项目 | 约定 |
|---|---|
| 空值占位 | `＿＿＿＿＿＿＿＿`（8 个全角下划线，引擎常量 `BLANK`）。**切勿手抄下划线字面量**（`docPlan.test.js` 中 4 个下划线的写法属历史夹具，不要照抄）。本文档中出现的 `＿＿＿＿＿＿＿＿` 均为渲染结果示意，非需手写的字面量。两种产出方式：绑 var 且值为空时自动落 BLANK；或用 `{ blank: true }` 恒定留白 |
| 章节自动编号 | ✅ 已由工程师实证：`buildSections()` 先判 `visibleWhen` 再进 `buildSection`，`headingCounter` 只在 `case 'heading'` 内自增 → **被隐藏的区块不消耗序号**。`group` 整体隐藏时其内部 heading 一并跳过；`group` 与父级共享同一 ctx，内外 heading 编号连续。已有回归测试守卫（`client/src/schemaDoc/docPlan.test.js:248`）。故本文两份模板均可放心使用 `autoNumber` + 条件章节 |
| 正文语言 | 简体中文；法定表格名称、上市规则条号、英文文书名保留原文（如 `Form ND2A`、`Consent to Act as Director`） |
| 签署人 | **一律自由填写文本格子，不关联 Claw 人员库**（已锁定规则） |
| 留白格子（三条硬规则） | 🔴 **① `value` 必须非空**：签署块每个格子的 `value` 要么写 `{ var: '真实字段' }`（用户可能填写的），要么写 `{ blank: true }`（纯手签、永不填写的）。<br>🔴 **② 严禁 `value: [{}]` / `value: []` / 省略 `value`** —— `resolveSegments` 会静默跳过，渲染成**无下划线的空白**，不报错、验收时肉眼极易滑过。<br>🔴 **③ 同一规则适用于 `paragraph.segments` 与 `infoTable.rows[].value`** —— 三处共用同一个 `resolveSegments`。<br>原理与实证见 §9.1 第 3 条 |

### 7.3.1 B16 固定条款文本（`clauseList` / `variant: 'checked'`）

1. 本人已于／将于 `{effectiveDate}` 或之前，交还所有属于本公司或其附属公司之财产、文件、会计记录、公司印章、门禁卡、名片及电子设备。
2. 本人已删除或交还所有以电子形式持有之本公司机密资料，并不会保留任何形式之副本。
3. 本人明白并同意，本人对本公司所负之保密责任于本人辞任后仍然持续有效，并将继续遵守普通法及本人任职期间根据《公司条例》(Cap. 622) 所承担而于离任后仍具效力之责任。
4. 本人同意在本公司提出合理要求时，签署及办理一切与本人辞任有关之文件（包括但不限于向香港公司注册处提交之 `Form ND2A` 及联交所所需之确认文件）。

| 设计点 | 依据与理由 |
|---|---|
| `hasDisagreement` 设为**必填 boolean** 而非仅凭 textarea 是否有内容判断 | 上市规则第 13.51(2) 条要求，董事辞任公告须载明辞任董事**是否**与董事会存在意见分歧。设为必填布尔可强制签署人作出明示选择，避免「漏填 textarea = 默认无分歧」这一高风险默认值。 |
| 🔴 `hasDisagreement` **刻意不设默认值**（Vincent 已拍板，非遗漏） | **这是有意的设计，请勿"修好"它。** 若预设为 `false`，公司秘书只要不动这个开关，文书就会自动生成「本人与董事会并无任何意见分歧」——一句**未经辞任董事确认、却以其名义作出、且将原文进入港交所公告**的法律声明。一旦该董事实际存在分歧，公司即构成虚假或具误导性披露。故：无默认值 → 未选择时禁用导出 → 强制人为决策。选「存在分歧」时 `disagreementDetail` 联动转必填，避免只勾选却不说明。<br>⚠️ 后续维护者若发现"这个 boolean 没给初值"，那不是 bug，是本条设计。 |
| `shareholderMatter` 采用 `truthy/falsy` 双分支 | 同属第 13.51(2) 条必备要素（是否有须提请证券持有人垂注之事项）。留空即自动生成否定声明，减少一个布尔字段，同时保证文书必然出现该项声明、不会缺漏。 |
| `committeeRoles` 用 `checklist` 而非 textarea | 委员会职务直接影响上市规则第 3.21 条（审核委员会须至少三名成员且过半为 INED、主席须为具备会计资历之 INED）与第 3.25 条（薪酬委员会）之合规；结构化勾选便于公司秘书据以判断是否需同步补选，亦便于日后提取为结构化数据。 |
| 保留 `directorType` | INED 辞任触发上市规则第 3.10 / 3.10A / 3.11 条（三个月补足期）与第 3.21 条审核委员会人数下限；执行董事辞任则可能触发第 3.05 条授权代表更替。公告用语亦须准确表述董事类别。 |
| 交还财产条款用 `clauseList` / `variant: 'checked'` | 逐条打勾形成可核对之交接清单，兼作公司秘书离任交接工作底稿。 |
| 明确「不提出申索」段落 | 减少离任纠纷；同时保留应付袍金与报销之除外条款，避免条款因显失公平而不获执行。 |
| `Form ND2A` 与 15 日期限写入 `note` | 《公司条例》(Cap. 622) 规定公司须于董事变更后 15 日内通知公司注册处处长并更新董事登记册；`note` 作为操作提示置于文末，不构成文书正文内容。 |
| 签署日期留空白线 | 辞任信应由董事亲笔签署并亲笔填日期，系统自动带入今日日期反而可能与实际签署日不符，产生证据瑕疵。 |

## 7.6 风险提示（需人工复核）

1. **🔴 意见分歧措辞（最高风险）**：`disagreementDetail` 的文字会被**原文或实质性地写入港交所公告**，并可能被监管机构、投资者及传媒引用。任何指称董事会失当之表述均须由公司法律顾问逐字审阅后定稿。系统不得对此字段做任何自动改写、摘要或美化。
2. **✅ 声明不可预设默认值 —— Vincent 已拍板采纳，转为实现要求**：`hasDisagreement` **不设默认值**，以「未选择」状态呈现；未作选择时**禁用导出按钮**，错误文案「请明确声明是否与董事会存在意见分歧 —— 该声明将原文进入港交所公告」；选「存在分歧」时 `disagreementDetail` **联动转必填**。详见 §7.2 及 §7.5 该条设计说明。
3. **🟠 「须提请股东垂注事项」的判断门槛**：何谓「须提请垂注」属主观判断，董事个人认知与公司立场可能不一致。建议公司秘书在董事填写前提供口头/书面指引，并保留董事原始填写版本存档。
4. **🟠 INED 辞任的连锁合规义务**：若 `directorType = 独立非执行董事`，辞任可能同时导致 INED 人数、审核委员会组成不符上市规则；本模板**不自动校验**，须由公司秘书另行核查并在三个月内补足。可在 UI 层加一条提示，但不写入正文。
5. **🟠 生效日期与公告时序**：上市规则要求董事变更「在切实可行范围内尽快」刊发公告。若 `effectiveDate` 早于文书生成日期（追溯辞任），须特别复核是否已构成延迟披露。
6. **🟡 法条引用**：文中所引《公司条例》(Cap. 622) 与上市规则条号以撰稿时通行版本为准；上市规则不时修订（尤其第 3 章企业管治相关条文），首次启用前请由公司秘书对照最新版本核对条号。
7. **🟡 双语需求**：港股上市公司公告须中英文同步刊发。本模板仅提供中文正文，若辞任董事为非中文使用者，须另备英文版本或加签英文译本；建议 Vincent 确认是否需要在后续版本增设英文 preset。

## 8.5 业务要点说明

| 设计点 | 依据与理由 |
|---|---|
| 独立成文的「同意出任」声明 | 香港《公司条例》(Cap. 622) 要求委任董事前须取得当事人同意；本函即该项同意之书面凭证，亦是提交 `Form ND2A` 之标准支持文件。缺此文件，董事委任之效力及注册处申报之完整性均存疑。 |
| `qualificationConfirmations` 用 `checklist` 而非散落 boolean | 九项资格确认在法律上是**一组并列的事实陈述**，逐项打勾既符合业界标准同意书格式，又将九个布尔字段压缩为一个字段，避免表单膨胀（这是本模板控制在 11 字段的关键）。 |
| 年满 18 岁 / 非破产 / 未被取消资格 / 非核数师 | 分别对应《公司条例》(Cap. 622) 董事最低年龄规定、破产人不得担任董事之限制、法院取消资格令（《公司（清盘及杂项条文）条例》(Cap. 32) 相关条文）、以及核数师独立性要求。此四项为香港董事适格性之基础门槛。 |
| 第 3.08 / 3.09 条确认写入 checklist | 上市规则第 3.08 条界定董事之受信责任与谨慎技能勤勉责任；第 3.09 条要求董事须令联交所信纳其具备品格、经验、诚信及与职位相称之能力。上市公司委任董事时须逐项取得书面确认，以备联交所查询。 |
| 第 3.13 条独立性章节用 `group` 条件包裹 | 独立性确认仅适用于 INED，对执行董事显示会造成误导。`group` 为透明容器，条件不成立时整节消失且不产生多余 DOM 层，正合此用。 |
| `independenceConfirmed` 设为可选 boolean 而非必填 | 现实中确有「董事会认定其仍属独立、但存在需披露之关系」之情形，上市规则允许此类情况但要求于公告中说明理由。设为可选并提供 `false` 分支文本，避免逼迫签署人作出不实确认。 |
| `otherDirectorships` 覆盖「过去三年」 | 上市规则第 13.51(2) 条要求董事委任公告披露获委任人于过去三年在其他上市公司担任之董事职务。此字段直接产出公告素材，避免公司秘书二次问询。 |
| 「过桥」承诺条款用 `ordered` 而非 `checked` | 承诺条款是**整体接受**（签署即全部承诺），无须逐条勾选；编号列表更符合法律文书体例，也避免签署人误以为可选择性接受。 |
| 个人资料章节 | 董事登记册须向公司注册处申报且部分内容供公众查阅，属《个人资料（私隐）条例》(Cap. 486) 下之个人资料收集与披露，须取得当事人明示同意并告知其查阅及更正权利。 |
| 送达地址而非住址 | 香港自新查册安排实施后，董事**住址**及完整身份识别号码受保护、不再对公众开放，公开可查阅者为**通讯／送达地址**及部分身份识别号码。本模板只收集送达地址，从源头降低私隐风险。 |
| 🔴 `idNumber` **完整显示、不作遮蔽**（Vincent 已拍板） | 本函是**递交香港公司注册处及联交所的正式存档件**，并作为提交 `Form ND2A` 之支持文件。遮蔽版（如 `K12****(7)`）可能因资料不完整被**退件**，反而拖延法定 15 日申报期限。脱敏需求应交由**流转环节**处理（对外分发时另行导出遮蔽版），模板本身**不维护双版本**——一份文书两种呈现会带来"哪份是正本"的存档歧义，风险高于收益。<br>⚠️ 此决策不减免私隐义务：PDPO 相关提醒仍保留于 §8.6 风险 4，Claw 端加密存储与访问控制照常执行。 |
| 设见证人签署块 | 同意出任董事函在争议场景（如董事否认曾同意出任）中属关键证据，加设见证人签署可显著提升证明力。签署人一律自由填写，符合已锁定之签署块规则。 |

## 8.6 风险提示（需人工复核）

1. **🔴 独立性确认的实质判断不可外包给模板**：`clauseList` 六条为归纳性表述，实际独立性评估须由提名委员会依上市规则第 3.13 条 (1)–(8) 项逐项分析（尤其「紧密联系人」「核心关连人士」之定义具技术性）。模板打勾**不构成**独立性认定，仅为董事自我声明。首次启用前须由公司秘书对照最新版上市规则核对条文对应关系。
2. **🔴 资格确认属法律陈述，虚假陈述有刑责**：向公司注册处提交载有虚假或具误导性陈述之文件属刑事罪行。UI 须明确提示签署人本函之法律后果，不得由公司秘书代为勾选。建议加「本人已阅读并理解上述各项」之独立确认动作。
3. **✅ 章节自动编号与条件显示的交互 — 已确认，风险解除**：引擎在条件求值**之后**才编号，隐藏的 `group` 及其内部 heading 不消耗序号，非 INED 版本不会跳号；且已有回归测试（`docPlan.test.js:248`）守卫此行为。本项由原「🟠 待确认」降级为已关闭，第三节按现规格实现即可。
4. **🟠 身份识别号码之存储与展示（呈现方式已定，私隐义务仍在）**：`idNumber` 属《个人资料（私隐）条例》(Cap. 486) 项下之敏感个人资料。
   - **模板呈现方式已由 Vincent 拍板：完整显示、不遮蔽**（理由见 §8.5），此项不再是待决问题。
   - **但以下私隐控制措施仍须落实**：(a) Claw 端**加密存储**，不得明文入库；(b) 模板导出件按机密文件管理，**限公司秘书处及获授权人士访问**，不得随附于对外分发的会议文件包；(c) 如需对外提供（如向承销商、律师行），应另行导出遮蔽版本，由**流转环节**而非模板层处理；(d) 保留访问日志以备查。

### 9.1 转写时的引擎细节（工程师实证，务必遵守）

1. **`blank` 一律省略**：`schemaUtils.js` 中 `BLANK = '＿＿＿＿＿＿＿＿'` 已是默认值。`segments` / `infoTable.value` / `signBlock.items[].value` 中**不写** `blank` 字段即自动落 8 个全角下划线。⚠️ 不要照抄 `docPlan.test.js` 老夹具里 `blank: '＿＿＿＿'`（4 个）的写法。本文档正文中显示的下划线均为**渲染结果示意**。
2. **`autoNumber` 与条件章节安全**：见 §8.4.1，隐藏区块不消耗序号，`group` 与父级共享 ctx、编号连续。两份模板均可放心用 `autoNumber`。
3. **🔴 留白格子用 `blank` 段（最易踩的坑，务必照做）**
   `resolveSegments()` 对每个 seg 依次判分支，若一个分支都进不去则**静默跳过、不 push 任何内容**——不报错、不告警。这是本规格中最危险的一处：产出的是**无下划线的空白格**，与正确的下划线在验收时肉眼几乎无法区分。

   | 写法 | 产出 | 结果 |
   |---|---|---|
   | `value: [{}]` / `value: []` / `value` 缺省 | `[]` | ❌ **空白，无下划线** |
   | `value: [{ blank: true }]` | `[{ text: BLANK, blank: true }]` | ✅ `＿＿＿＿＿＿＿＿` |
   | `value: [{ blank: '＿＿＿＿' }]` | `[{ text: '＿＿＿＿', blank: true }]` | ✅ 自定义长度留白 |
   | `value: [{ var: 'x' }]`，`x` 未定义或为 `''` | `[{ text: BLANK, blank: true }]` | ✅ `＿＿＿＿＿＿＿＿` |
   | `value: [{ var: 'x' }]`，`x = '张三'` | `[{ text: '张三' }]` | ✅ `张三` |

   **两条选择规则**：
   - **用户可能填写的格子**（签署人姓名、职务等）→ 绑**真实字段** `{ var: 'directorName' }`，并在 `fields` 中定义。填了显示值，没填自动出 BLANK。
   - **纯手签、永不填写的格子**（手写签名、见证人栏、公司秘书收讫栏）→ 用 `{ blank: true }`。

   ❌ 不要写 `value: [{}]`；❌ 不要写 `value: '＿＿＿＿＿＿＿＿'`（硬编码字面量，长度易错）；❌ **不要引用 `fields` 中不存在的「哑 var」**——该写法虽能产出下划线，但靠"引用不存在的字段"这一副作用生效，后人见 signBlock 引用查无此项的 key 会误判为笔误而删除，导致缺陷无声复发。`blank` 段是引擎的一等公民语法，语义自明。

   ⚠️ **同一个坑波及三处**：`resolveSegments` 由 `paragraph.segments`、`infoTable.rows[].value`、`signBlock.items[].value` **共用**。本规格中所有 `infoTable` 行（模板 7 的 B3 五行 + 模板 8 的 C3 六行，共 11 行）均已绑真实字段，经逐行复查无一例外，故仅 `signBlock` 受影响；但**日后新增任何留白行时同样适用此规则**。

   签署人一律自由填写，不接 Claw 人员库，填写视图亦不查人员表。
4. **`objectTable.blankWhen` 三态**：本次两份模板均未使用 `objectTable`，该特性不适用；如日后扩充「离任后是否仍持股」这类可 N/A 的表格列时再启用。
5. **🔴 `layoutMode` 必须显式写 `'custom'`（漏写则全部正文结构失效）**
   引擎 `layoutMode` 的**默认值是 `'auto'`**，会依据 `fields` 顺序自动排版，**完全无视手写的 `layout.sections`**。两份 preset 的元信息中都必须显式声明 `layoutMode: 'custom'`，否则本文档 §7.3（20 区块）与 §8.3（23 区块）的全部正文结构、条件章节、签署块设计一律不生效。
   ⚠️ 与第 3 条同属「静默失败」类缺陷：**不会报任何错**，只是生成的文档结构与设计对不上。转写完成后请对照 §7.4 / §8.4 的成文示例做一次人工对拍，不要仅凭"能导出、不报错"判定通过。
